# 视频标题

围绕一个能被内容兑现的**承诺**生成标题。技术类使用专门参考，其他视频使用通用流程；评价与比较只辅助生成、改写和精修。

## 边界与优先级

- 使用用户提供的文字、本地脚本或提纲作为内容依据，封面图片作为辅助上下文。只有链接或视频文件时，请求文字材料或交接给已有读取能力，取得材料后再继续；文件名不能证明内容。
- 只负责标题，不自动扩展为简介、封面设计、开场改写、视频解析、音频转录、热点或联网研究。
- 依次优先满足：**事实与承诺边界 → 用户明确要求 → 默认策略与表达偏好**。指定措辞和原标题都不作为事实证据。
- 要求冲突时简短说明并提出最小调整。确实无法凑足合格候选时说明原因、交付可成立的版本；先充分探索，不以重复或夸大填数。

## 1. 识别分支

- **生成**：需要新标题。
- **改写**：调整原标题；保留内容事实和用户明确指定的元素，其余角度、结构和措辞可调整。
- **精修**：已选定标题或方向，再调整长度、措辞或悬念程度；沿用对话材料和已选方向。
- 显式调用但载体不明时，先澄清是否为视频；不要把调用本身当作内容事实。

完成条件：确定本轮分支及需保留、调整的元素。

## 2. 判断材料是否充分

区分**内容事实**与**表达策略**：

- 内容事实：实际任务、结论、结果，以及拟用于标题的数字、效果和个人经历。缺失且影响承诺时必须补问，不能推测补齐。
- 只有主题时，先问视频实际解决什么问题或讲出什么结论；只有原标题的改写任务同样适用。
- 表达策略：受众、主要内容目的、发现入口。材料支持时合理推断并简短注明假设；只有不同选择会明显改变方向且无法判断时才追问。
- 只补影响真实性或方向的缺口，不要求完整表单。

完成条件：材料支持一个明确承诺，表达策略已确定或合理假设。未达到时只提出必要补问，等待回答。

## 3. 路由与策略

按**视频大类 → 主要内容目的**选择方法。混合内容可保留多个属性，但选择一个主要目的驱动生成；不让用户先填分类菜单。内容目的与标题表达风格分开判断。

**技术类（编程、AI Coding、技术知识分享）**：生成或改写前，读取 [技术标题参考](references/technical-title-patterns.md)，选择相关内容目的、表达风格和场景检查。精修仅在当前上下文已有该参考且内容目的未变时复用。非技术任务不加载，直接使用本文件的通用流程。

按下列条件调整策略：

| 条件 | 行为 |
| --- | --- |
| 搜索入口 | 保留能识别具体任务、API 或错误的关键词，突出实际问题 |
| 推荐浏览 | 从目标观众可识别的现象、收益或冲突引入，不隐藏必要主题信息 |
| 系列追更 | 说明本集新成果；脱离合集也应基本可理解 |
| 入口未知 | 兼顾问题识别与兴趣，不强制追问、不为每种入口各出一套 |
| 专业开发者 | 保留关键 API、错误名等辨识信息 |
| 泛技术观众 | 优先可识别现象，保留定位主题所需的技术对象，不堆全部术语 |
| 未指定语言或平台 | 默认中文、平台中性，保留必要英文技术 Keyword；未知平台不阻塞 |
| 指定平台 | 按明确要求调整表达、长度；不臆造平台机制或字数规则，不默认生成多平台版本 |
| 已有封面／封面文案 | 标题补充信息，减少机械重复，允许必要 Keyword 重复 |
| 已有脚本／开场 | 检查与标题是否兑现同一承诺；不匹配时调整标题并简短指出问题 |

没有封面或开场不阻塞，也不声称已检查缺失材料。短而清楚优先，不将 12～18 个汉字当成硬限制。

完成条件：确定主要内容目的、受众、入口策略，并应用相关条件和技术参考。

## 4. 生成与检查

### 数量与差异

- 默认生成／改写 **5 个**，至少 **3 个有实质差异的表达方向**：术语、症状、成果或真实 Hook。只替换“快速／轻松”等修饰词不算差异。
- 内容支持时优先多个 Hook；内容承诺单一时可围绕同一承诺改变表达，不硬凑误区、反常识或扩大范围。
- 默认精修至少 **3 个同方向版本**，通过措辞、长度或悬念程度体现差异，不重新打散方向。
- 用户指定数量时遵循指定数量；少于 3 个不要求三个方向，多个候选仍要有实质差异。冲突按“边界与优先级”处理。

### 逐个检查，再检查整组

1. **兑现**：每项事实表述在材料中有依据；数字、效果、时限和经历尤其核对。强化表达，不强化事实。
2. **范围**：概念速览与操作能力、成功路径 Demo 与完整生产方案、单因排查与全部原因、场景优势与全面胜出分别匹配；播放时长不等于完成任务所需时长。
3. **识别与相关**：主题可识别、必要 Keyword 保留，有目标观众的观看理由。
4. **单一主 Hook**：突出一个主要吸引点，表达清楚；无需同时塞入对象、问题、收益和悬念。只支持平实表达时优先真实清楚。
5. **信息前置**：主要问题或成果在前，集数和非必要品牌在后；标题只保留最重要的技术对象，其他依赖留给简介。
6. **整组差异**：数量和差异满足本轮分支及用户要求；不合格候选先修改或替换。

完成条件：每个候选通过事实、范围和表达检查，整组通过数量与差异检查；无法同时满足时按冲突规则说明例外。

## 5. 输出与收敛

默认呈现：

1. 用一两句话说明受众、核心承诺及必要假设，材料充分时直接输出，不增加确认关卡。改写时简短指出原题主要问题。
2. 编号列出候选，每个附一句简短理由，体现其表达方向或适用条件。
3. 推荐一个：依次按**内容匹配 → 受众与入口匹配 → 清晰度与吸引力**选择；没有明确优势时说明首选、备选的取舍，由用户决定。

用户要求“只给标题”时省略分析、理由和推荐，内部仍执行全部检查。要求之间冲突时仍作必要说明，不默默违背要求。

评价保持定性且有材料依据：不预测点击率，不宣称推荐标题点击率最高，不用无依据数值评分，不保证搜索排名或展示效果。

完成条件：按本轮数量与呈现要求交付；有反馈时回到步骤 1，选定方向后的调整走精修。
