# Technical Covers

Technical covers should make abstract engineering ideas visible without turning into documentation.

## Concept Extraction

Reduce the video to one cover idea:

- Problem: what pain or bug does the video resolve?
- Shift: what changes after watching?
- Mechanism: what tool, pattern, or architecture creates the change?
- Surprise: what is counterintuitive or newly possible?

Use only one of these as the cover center.

## Metaphor Library

- Architecture evolution: layers, bridges, modules, routes, city blocks, cutaway systems.
- Debugging: spotlight, breakpoint, trace line, log stream, magnifying panel, before-after failure state.
- AI agent workflows: workbench, tool belt, orchestration board, branching routes, handoff lanes, function-call network.
- Performance: bottleneck, pressure gauge, fast lane, compression, heat map, flow meter, narrow pipe opening.
- Refactoring: dismantle and rebuild, clean module boundaries, tangled-to-ordered paths, labeled blocks rearranged.
- Type systems and correctness: contracts, locks, rails, puzzle pieces, stamps, gates, compile-time checkpoint.
- DevOps and deployment: pipeline, release gate, staged runway, environment stack, traffic switch.
- Security: boundary, sealed channel, key exchange, permission gate, audit trail.

## Code And UI

Use code only as texture or a small recognizable fragment. Never make dense code the main readable content.

Use UI screenshots only when the UI is the product or the result. Crop to the one interaction that matters.

Use diagrams as simplified symbols. Do not put a complete architecture diagram on the cover.

## Hook Writing

Prefer short, concrete cover text:

- "Agent Memory"
- "Stop Rewriting"
- "Fast Builds"
- "Typed Boundaries"
- "One Bad Abstraction"
- "Debug The Loop"

Let the video title carry the full explanation. Let the cover create recognition and curiosity.
