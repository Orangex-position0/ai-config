# 文档契约

在项目预检通过后首次建档，或在恢复、更新确认版本时读取。以下字段是运行产物的最小契约，不要求照抄空模板。

## 目录与事实来源

使用项目预检已确认的本地项目根目录，在其中写入 `docs/ui/<project>/`；不把当前工作目录自动视为用户项目。`<project>` 使用已确认的 lowercase-hyphens slug。写入前检查目录是否可写及已有文件；发现同名项目先确认是否恢复，不覆盖。

| 文件 | 权威内容 |
| --- | --- |
| `design-spec.md` | PRD、品牌、视觉方向、Design System 的设计决策 |
| `progress.md` | 执行位置、状态、设计工具、确认记录、版本证据与阻塞 |
| `flows/<flow>.md` | 本批范围、页面状态、HTML 原型与可选设计工具定位及 Review 结果 |

已有 PRD 记录路径或 URL、章节及版本证据；从原文件读取需求。新增决策写回用户授权的来源，或记录为明确的补充项，不复制整份 PRD。拆分文件时保留索引并更新所有引用。

## design-spec.md

首次创建或进入本文件的新阶段时，读取 [design-spec 模板](../assets/templates/design-spec.md)，以模板作为字段与排版的唯一来源。复制到用户项目后替换项目名；仅展开当前阶段提示，未来阶段保留标题与“未开始”。已有文档按当前阶段补齐，不重新覆盖。

四个阶段使用稳定 ID `prd`、`brand`、`visual`、`system`；确认状态引用 `progress.md`。选择本地编写或引用已有 PRD 的一种方式，删除不适用说明；填写后删除对应提示注释。开发交接仅在本轮流程全部通过 Review 后填写。

## progress.md

首次建档或更新执行记录时，读取 [progress 模板](../assets/templates/progress.md)，以模板作为字段与排版的唯一来源。当前情况放顶部，阶段与流程批次分别维护；确认和阻塞历史追加保留。已有文件原位更新，不用模板覆盖。

待确认基线与已批准记录分开。确认失效时撤下当前有效引用，在待重新审核项中关联历史记录；新确认追加新记录，不改写旧的用户决定。

### ID 与证据目录

每个项目分别维护单调递增且不复用的 ID：`review-001`、`blocker-001`、`change-001`。修订、失败后重试或重新审核使用下一个 ID；历史记录保持原 ID。恢复时从 `progress.md` 和已有 `evidence/` 取当前最大序号，不因记录关闭而重新编号。

每个待确认基线使用 `evidence/<review-id>/`，最小结构如下；只创建本次实际有内容的条目：

```text
evidence/review-001/
├── manifest.md
├── documents/<文档根目录内的相对路径>
├── external/<固定来源快照>
├── prototype/<批次源码或视觉快照>
└── design-tool/
    ├── batch.structure.<ext>
    └── <key-screen>.visual.<ext>
```

`manifest.md` 记录关卡、确认范围、交付模式、当前视觉载体、原始来源或路径、快照相对路径和稳定定位。HTML 分支记录源码版本、运行入口和批次截图；设计工具晋升分支记录文件、关键页面/节点及一次合并结构证据与对应视觉证据。定位文件名将 `:` 等路径不安全字符替换为 `-`，原始引用只保存在 manifest。目录只随实际证据创建；必要证据无法持久化时保持待确认，并记录缺失项和解除条件。

### 版本证据

使用可取回、可比较的内容作为确认基线，不手工维护散列。每次请求确认前固定基线，记录文件和章节范围；用户确认时核对当前内容仍与展示版本一致，变化后重新展示并请求确认。

- Markdown：优先引用与本次展示内容一致的已有 Git commit、文件路径及阶段章节。存在未提交改动、未跟踪文件、无 Git 或旧版本无法取回时，在 `evidence/<review-id>/` 保存相关文档的完整快照，并记录本次确认的章节范围；用户的 Git 历史保持原状。
- 外部 PRD：引用可取回的固定版本；来源可变或无版本时，保存本次使用内容的快照及来源。仅有 URL 或时间戳不足以比较变化。
- HTML/CSS 原型：记录源码路径、运行入口、固定版本及批准截图；无法保存可运行版本时保持待确认。HTML Review 通过后冻结该工作稿，不与设计工具长期双向同步。
- 可编辑设计工具：仅在用户批准晋升或直接工具模式下记录工具、文件和关键页面/节点定位。每批保存一次合并结构回读和关键页面视觉快照；工具无法取回历史内容时，把这些证据保存在同一目录。
- 快照一经展示便保留原样；修订使用新的 review ID。证据目录只作为审核附件。必要基线无法保存或取回时，记录缺口并保持待确认或待重新审核。

恢复时取回基线，对比本次确认范围内的内容：纯格式变化记录为无设计影响；需求、视觉或交互变化按主流程进入影响分析和重新审核。设计工具或 HTML 原型的变化按相关定位对象或源码核实，时间戳只作为定位信息。使用完整文件快照时，审核范围限定为记录的章节，使后续章节可以独立演进。

## flows/<flow>.md

开始当前设计批次时，读取 [flow 模板](../assets/templates/flow.md)，以模板作为字段与排版的唯一来源，保存为 `flows/<flow>.md`。范围确认前只填写流程定义、本批范围、页面与状态清单；确认后随实际设计、Review 和交接逐步展开后续部分。

自检清单与问题记录分开，用户接受的遗留项保留问题事实。范围确认与最终验收引用 `progress.md`；已有文件原位更新，保留问题与处理记录。通过模板中的需求到节点映射检查遗漏，计划节点不冒充已生成节点。
