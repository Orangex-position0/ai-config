# ECC Authoring

> 用于创建或审查 Rule / Skill 时的分层约束：Rule 写底线，Skill 写落地。

## 1. Why

Rule 和 Skill 承载不同形态的知识。混写会导致 Rule 过长、Skill 缺少原则锚点，最终让 Agent 既难触发也难遵循。

## 2. What

| 分类 | 承载内容 | 不承载内容 |
|------|----------|------------|
| Rule | 跨语言、跨项目、跨场景的原则、红线、判断标准 | 长流程、命令清单、完整教程 |
| Skill | 任务导向流程、工具使用、检查清单、正反例 | 可抽离为全局底线的原则 |

## 3. How

- 新建 Rule 时，只写"必须 / 禁止 / 应该"这类可判断约束。
- 新建 Skill 时，把相关 Rule 作为不可违反的底线引用，再写具体执行步骤。
- 当 Rule 出现大段步骤、命令、完整案例时，拆成"短 Rule + Skill"。
- 当 Skill 出现跨场景通用红线时，抽成 Rule，并在 Skill 中引用。
- 不为单次需求新增 Skill；只有可重复触发的任务流程才值得沉淀。
