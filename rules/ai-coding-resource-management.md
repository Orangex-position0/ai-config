# AI Coding 资源管理体系

> 用于创建或审查 AI Coding 资源时的分层约束：启动上下文写索引和红线，Rule 写底线，Skill 写落地，Command 写入口，Agent 写角色，Hook / script 写确定性护栏。

## 1. Why

AI Coding 配置会随着使用变长。把所有知识塞进启动上下文，会浪费 context，也会让 Agent 难以判断该用什么能力。

正确做法是按需加载：默认只放不可违反的约束和导航；任务需要时，再通过 Rule、Skill、Command、Agent、Hook 或 script 承载更具体的能力。

## 2. What

| 载体 | 加载方式 | 应放内容 | 不应放内容 |
|------|----------|----------|------------|
| `CLAUDE.md` / `AGENTS.md` | 默认读取 | 项目不变量、红线、目录导航、能力路由 | 大量示例、教程、完整流程 |
| Rule | 路径或全局约束加载 | 原则、边界、可判断的必须 / 禁止 | 长流程、命令清单、完整案例 |
| Skill | 语义触发后读取 | 可复用任务流程、检查清单、工具用法、模板导航 | 全局底线、单次需求记录 |
| Command | 用户显式调用 | 高频任务入口、参数化流程 | 完整知识库、低频专项能力 |
| Agent | 委派时加载 | 审查者、测试者、安全专家等独立职责 | 通用项目规则全集 |
| Hook / script | 事件或命令触发 | 格式化、检查、阻断危险操作等确定性行为 | 需要语义判断的建议 |
| Plugin / 配置仓库 | 安装时生效 | 一组可分发的 rules / skills / commands / agents / hooks | 单篇超长规则 |

## 3. How

- 默认上下文只保留稳定约束和资源索引；详细方法迁入 Skill 或引用文档。
- 新建 Rule 时，只写可判断约束；不要写教程、长示例或执行步骤。
- 新建 Skill 时，在 `description` 写清触发场景；正文只写核心流程，长示例放 `references/`，可重复检查放 `scripts/`，模板放 `templates/` 或 `assets/`。
- 新建 Command 时，只为高频、用户会主动点名的流程建入口；专项能力优先建 Skill。
- 新建 Agent 时，只写角色职责、输入输出、何时委派；项目通用规则通过启动上下文或相关 Rule 提供。
- 新建 Hook / script 时，只承载确定性动作；涉及判断、取舍、权衡的内容留给 Rule 或 Skill。
- 当 Rule 变成操作手册时，拆成"短 Rule + Skill"。
- 当 Skill 出现跨场景硬约束时，抽成 Rule，并在 Skill 中引用。
- 不为单次需求新增资源；只有会重复触发、能减少未来判断成本的内容才沉淀。

## 4. Checklist

- [ ] 启动上下文是否只包含红线、项目不变量和资源索引？
- [ ] Rule 是否短、可判断、无长流程？
- [ ] Skill 是否有清晰 `description`，且只在触发后需要？
- [ ] Command 是否是用户显式高频入口？
- [ ] Agent 是否有独立职责，而不是复制通用规则？
- [ ] Hook / script 是否确定、可自动执行、少依赖语义判断？
- [ ] 同一条规则是否只存在一个权威位置？
